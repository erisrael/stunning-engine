## 1. Introduction

### 1.1 Purpose
This System Requirements Specification (SRS) establishes the authoritative technical and functional baseline for the MySeed Academy digital learning platform, encompassing the public web portal (`apps/web`), the administrative content and operations console (`apps/admin`), the backend RESTful API services (`services/api`), and shared domain packages (`packages/ui`, `packages/database`, `packages/types`). This document adheres to the structure and principles defined in **ISO/IEC/IEEE 29148:2018** (Systems and software engineering — Life cycle processes — Requirements engineering) and supersedes the legacy **IEEE Std 830-1998** format, while maintaining full backward-compatibility with IEEE 830 section cross-references.

### 1.2 Document Conventions
- **Requirement Identifiers:** Formatted as `REQ-[SUBSYSTEM]-[CATEGORY]-[NUMBER]`, e.g., `REQ-CORE-FEAT-001`.
- **Requirement Weight / Priority:**
  - **SHALL [P0]:** Mandatory requirement; release blocking.
  - **SHOULD [P1]:** Highly desirable feature; deferred only under documented mitigation.
  - **MAY [P2]:** Optional optimization or future evolution item.
- **Typography:**
  - `Code literals`, REST paths, and schema objects appear in monospace font.
  - Mathematical equations and constraints follow KaTeX syntax.
- **Cultural & Linguistic Standards:** Ethiopian calendar / Gregorian conversions must be handled transparently; Amharic (አማርኛ) and English (UK/US standard) maintain tier-one parity across user-facing strings.

### 1.3 Intended Audience and Reading Suggestions
1. **Software Architects and Engineers:** Focus on Sections 2.1, 3.1, 3.2, 3.3, and 5 for architectural patterns, interfaces, and constraints.
2. **Quality Assurance (QA) & Test Engineers:** Section 4 (Requirements Traceability Matrix) and acceptance criteria in Section 3.2 dictate test suite verification.
3. **Product Managers & Content Leads (Teacher Dani & Team):** Sections 1.4, 2.2, and 2.3 define pedagogical boundaries, user workflows, and feature scopes.
4. **Site Reliability & DevOps Engineers:** Section 2.4, 3.3, and 3.4 for container specifications, network profiles, and failover topologies.

### 1.4 Project Scope
MySeed Academy is an Ethiopian educational technology ecosystem engineered by MySeed EdTech PLC. It delivers high-impact, teacher-led STEM (Science, Technology, Engineering, and Mathematics) education targeting Ethiopian students in Grades 5 through 12, with specialized matriculation exam preparation for Grades 8, 10, and 12.

The platform provides:
- A server-rendered, localized public educational portal supporting nine languages (Tier 1: English, Amharic; Tier 2: Spanish, French, Arabic RTL, Mandarin, Hindi, Portuguese, Russian).
- An offline-resilient, mobile-optimized learning loop: "Watch (Video), Understand (Reading), Practise (Interactive Checkpoints), Improve (Analytics & Progress Tracking)".
- A high-throughput administrative console featuring bilingual CMS, versioned page builder, automated Tier 2 translation dispatch, Tiptap rich-text publishing, and an encrypted vault for external integrations.
- An idempotent, multi-gateway donation and student sponsorship engine supporting national Ethiopian payment rails (Chapa, Telebirr, CBE Birr) and international cards (Stripe).
- A zero-downtime, self-healing modular monolith backend utilizing PostgreSQL 16 with an automated, Prisma-compatible in-memory database fallback.

## 2. Overall Description

### 2.1 Product Perspective
MySeed Academy operates as a distributed web and mobile client ecosystem serviced by a central API modular monolith:

```text
graph TD
    subgraph Client Tier
        W["apps/web (Next.js 14 SSR)"]
        A["apps/admin (Next.js 14 Console)"]
        M["Mobile Apps (Android / iOS / PWA)"]
    end

    subgraph CDN & Edge Gateway
        CDN["Edge CDN (Cloudflare / Vercel Edge)"]
        WAF["Web Application Firewall & Rate Limiting"]
    end

    subgraph Service Tier
        API["services/api (Express 4 + TypeScript)"]
        VAULT["AES-256-GCM Vault Service"]
        TRANS["Translation Engine (Google / Claude)"]
        PAY["Payment Engine (Chapa / Stripe)"]
    end

    subgraph Data & Storage Tier
        PG[("PostgreSQL 16 Primary")]
        MEM[("Automated Memory Store Fallback")]
        S3[("S3 / Cloudflare R2 Media Vault")]
        REDIS[("Redis Caching / Rate Limit")]
    end

    W --> CDN
    A --> CDN
    M --> CDN
    CDN --> WAF
    WAF --> API

    API --> PG
    API -.->|Failover on connection drop| MEM
    API --> S3
    API --> REDIS
    API --> VAULT
    VAULT --> TRANS
    VAULT --> PAY
```

### 2.2 Product Functions
1. **Interactive Course Delivery:** Delivery of Ethiopian curriculum STEM video lectures, reading modules, and interactive assessments partitioned by Grade Bands (5–6, 7–8, 9–10, 11–12).
2. **Bilingual Authoring & Dual-Tier Translation:** Creation of primary content in English and Amharic with automated translation dispatch to seven Tier 2 target languages.
3. **Student Sponsorship & Donation Lifecycle:** End-to-end checkout processing 399 ETB student sponsorships via Chapa/Telebirr and international currencies via Stripe with automated receipt generation and campaign attribution.
4. **Dynamic Page Construction & Design System Enforcement:** Drag-and-drop page assembly in the admin console with live preview at 320px, 390px, 768px, 1280px, and 1920px viewports.
5. **Self-Healing Data Resilience:** Transparent failover from PostgreSQL to an in-memory Prisma-compliant store to maintain 100% read/write uptime during infrastructure outages.

### 2.3 User Classes and Characteristics
- **Student Learners (Grades 5–12):** 
  - Technical competence: Basic to moderate smartphone literacy.
  - Access conditions: Low-end Android smartphones (Tecno, Infinix, itel), high latency (2G/3G/4G), intermittent power and connectivity.
- **Educators & Content Managers (Teacher Dani & Staff):**
  - Technical competence: Proficient with web CMS tools and media uploading.
  - Role: Authors bilingual curricula, reviews machine-translated strings, tracks cohort performance.
- **Donors and Sponsors:**
  - Technical competence: High familiarity with digital payments (Telebirr in Ethiopia, Credit Cards globally).
  - Role: Funds individual or group sponsorships (399 ETB / student / month); monitors impact ledger.
- **Platform Administrators & System Operators:**
  - Technical competence: High software engineering and DevOps literacy.
  - Role: Manages RBAC, rotates integration secrets, inspects telemetry, handles deployments.

### 2.4 Operating Environment
1. **Server-Side Runtime:** Node.js v20.12.0 LTS (or higher), Linux x86_64 / Alpine Docker images, Docker Compose v2.
2. **Database Engine:** PostgreSQL 16.2 with connection pooling (PgBouncer); Redis 7.2 for caching and session rate limits.
3. **Client-Side Browsers:** Google Chrome Mobile (v90+), Safari Mobile (iOS 15+), Phoenix Browser, Opera Mini (high-data savings mode), Firefox (v100+).
4. **Network Profiles:** Ethio Telecom 3G/4G cellular networks, Safaricom Ethiopia networks, localized school WiFi routers, and offline cached modes.

### 2.5 Design and Implementation Constraints
- **Monorepo Architecture:** Single repository managed via Turborepo and npm workspaces.
- **Language Uniformity:** TypeScript across all client, admin, and backend layers.
- **Accessibility:** Strict WCAG 2.2 AA conformance across all nine locales. Zero emoji in UI strings.
- **Security:** Zero plaintext secrets in database or logs. AES-256-GCM encryption for third-party keys.
- **Storage Limits:** Media uploads capped at 10MB per asset with magic-byte verification and SVG sanitization.

### 2.6 User Documentation
- Living component documentation accessible at `/design-system`.
- In-console integration guides with interactive credential validation.
- Standard operating procedures and runbooks stored under `OPS doc/`.

### 2.7 Assumptions and Dependencies
- **Telecommunications:** Ethio Telecom API gateways (Chapa/Telebirr) maintain at least 99.0% network availability.
- **Third-Party APIs:** Resend, Anthropic Claude, and Google Cloud Translation APIs remain reachable within 1500ms timeout windows.

## 3. Specific System Requirements

### 3.1 External Interface Requirements

#### 3.1.1 User Interfaces
- **REQ-UI-001 (Design System):** The UI shall render components derived from the Watermelon UI adaptation layer (`packages/ui`) with full dark/light theme switching.
- **REQ-UI-002 (Typography & Localization):** The system shall load subset webfonts: `Noto Sans Ethiopic` for Amharic and `Noto Sans Arabic` for Arabic with full right-to-left (`dir="rtl"`) layout flipping.
- **REQ-UI-003 (Responsive Breakpoints):** Layouts shall adapt smoothly across 320px (ultra-compact mobile), 390px (standard smartphone), 768px (tablet), 1280px (laptop), and 1920px (desktop).

#### 3.1.2 Hardware Interfaces
- **REQ-HW-001 (Low-Memory Devices):** Client JavaScript bundle per route shall not exceed 180KB gzipped to prevent out-of-memory crashes on 1GB RAM Android Go devices.
- **REQ-HW-002 (Touch Targets):** All interactive buttons and inputs shall maintain a minimum touch target size of 44x44 CSS pixels.

#### 3.1.3 Software Interfaces
- **REQ-SW-001 (PostgreSQL 16):** Database communications shall be routed through Prisma Client with parameterized SQL queries.
- **REQ-SW-002 (Payment Gateways):**
  - Chapa API (v1) for ETB currency transactions, supporting Webhook signature validation (`x-chapa-signature`).
  - Stripe Checkout API for USD/EUR/GBP transactions with HMAC-SHA256 signature checks.
- **REQ-SW-003 (Translation Services):** Pluggable integration supporting Google Cloud Translation API (v2) and Anthropic Claude 3.5 Sonnet.

#### 3.1.4 Communications Interfaces
- **REQ-COM-001:** All client-to-server traffic shall require HTTPS (TLS 1.3 preferred, TLS 1.2 minimum).
- **REQ-COM-002:** REST APIs shall adhere to JSON serialization with `Content-Type: application/json; charset=utf-8` and propagate `X-Request-ID` headers.

---

### 3.2 System Features & Functional Requirements

#### 3.2.1 Core Learning & Course Consumption Engine
- **REQ-FEAT-LEARN-001 [P0]:** The system shall categorize courses strictly by Ethiopian Curriculum Grade Bands: Grade 5–6, Grade 7–8, Grade 9–10, and Grade 11–12.
- **REQ-FEAT-LEARN-002 [P0]:** Video lessons shall be served via adaptive bitrate HLS streams with fallback MP4 streams at 360p, 480p, and 720p.
- **REQ-FEAT-LEARN-003 [P0]:** Every lesson shall present an interactive practice checkpoint before marking the lesson as completed.

#### 3.2.2 Dual-Tier Multilingual Content Management
- **REQ-FEAT-CMS-001 [P0]:** The admin content editor shall mandate both English (`en`) and Amharic (`am`) text fields before allowing an entity to publish.
- **REQ-FEAT-CMS-002 [P1]:** Saving an entity shall automatically enqueue asynchronous translation jobs for Tier 2 languages (ar, fr, es, zh, hi, pt, ru).
- **REQ-FEAT-CMS-003 [P0]:** Manual editor overrides of machine translations shall be permanently preserved and never overwritten by subsequent automated translation syncs.

#### 3.2.3 Student Sponsorship & Donations
- **REQ-FEAT-DON-001 [P0]:** The donation engine shall offer preset tiers: 1 Student (399 ETB/mo), 3 Students (1,197 ETB/mo), 5 Students (1,995 ETB/mo), or custom amounts.
- **REQ-FEAT-DON-002 [P0]:** Webhooks from Chapa and Stripe shall be processed idempotently; duplicate webhook events shall return HTTP 200 without executing duplicate database mutations.
- **REQ-FEAT-DON-003 [P1]:** Upon successful transaction confirmation, an automated bilingual tax-deductible receipt shall be delivered via email.

#### 3.2.4 Administrative Role-Based Access Control (RBAC)
- **REQ-FEAT-AUTH-001 [P0]:** Passwords shall be hashed using PBKDF2 with HMAC-SHA512 over 100,000 iterations and a unique 32-byte salt.
- **REQ-FEAT-AUTH-002 [P0]:** System shall enforce predefined roles: `Super Admin`, `System Admin`, `Content Manager`, `Donation Manager`, `Developer`, and `SEO Manager`.
- **REQ-FEAT-AUTH-003 [P0]:** The `Developer` role shall be strictly prohibited at both API and UI levels from accessing donor personal data and vault integration credentials.

#### 3.2.5 Automated In-Memory Fallback Mechanism
- **REQ-FEAT-DB-001 [P0]:** If PostgreSQL becomes unreachable during bootstrap or runtime, the API shall transparently switch to `MemoryClient` within 250ms without crashing.
- **REQ-FEAT-DB-002 [P1]:** In-memory operations shall execute all standard CRUD operations using pre-seeded bilingual fixtures with warning logs dispatched to `/healthz`.

### 3.3 Non-Functional Requirements

#### 3.3.1 Performance Requirements
- **REQ-PERF-001:** Under simulated 3G network conditions (1.5 Mbps bandwidth, 300ms RTT), First Contentful Paint (FCP) on the web portal shall occur in $\le 1.8\text{ seconds}$.
- **REQ-PERF-002:** The REST API shall achieve a 95th percentile latency ($p95$) of $\le 120\text{ ms}$ for read endpoints under a load of 1,000 requests per second.
- **REQ-PERF-003:** In-memory fallback queries shall execute with latency $p99 \le 5\text{ ms}$.

#### 3.3.2 Reliability and Availability
- **REQ-REL-001:** The platform shall guarantee $\ge 99.9\%$ operational uptime per calendar month, excluding scheduled maintenance windows.
- **REQ-REL-002:** Mean Time to Recovery (MTTR) for API service crashes shall be $\le 10\text{ seconds}$ via container restart policies.

#### 3.3.3 Scalability
- **REQ-SCAL-001:** The stateless API tier shall scale horizontally behind a reverse proxy to handle up to 25,000 concurrent active learners.
- **REQ-SCAL-002:** Database read replicas shall be supported without application code changes via connection string segregation.

---

### 3.4 Security and Compliance Requirements
- **REQ-SEC-001 (Secret Vault):** All external API keys and secrets stored in the database shall be encrypted at rest using AES-256-GCM with authenticated key derivation.
- **REQ-SEC-002 (HTTP Headers):** The web server and API shall emit strict security headers:
  - `Content-Security-Policy: default-src 'self' ...`
  - `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`
  - `X-Frame-Options: SAMEORIGIN`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
- **REQ-SEC-003 (Rate Limiting):**
  - Public endpoints: 100 requests per minute per IP.
  - Authentication endpoints (`/api/auth/login`): 5 failed attempts per 15-minute window per IP.
  - Payment initiation: 10 requests per minute per IP.
